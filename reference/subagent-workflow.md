# 子代理工作手册：PPT / PDF 逐页解析（阶段一+阶段二）

> **你只负责阶段一（脚本提取）和阶段二（逐页视觉校准），不做阶段三（全页复核）。完成后将初稿 docx 路径回报给主代理。**
>
> **禁止自复核、禁止声称“已复核”。复核由主代理负责。**

> ⚠️ **维护提醒：本文件的标记符号系统、输出模板与 SKILL.md 中各有一份完整副本。修改任一处时，必须同步更新另一处。**

## 1. 前置检查

### 1.1 识图能力

你通过 `read` 工具读取本地图片文件进行视觉识别。如果当前模型无法识图，立即停止并回报主代理。

### 1.2 系统依赖

- PDF 输入：无需 LibreOffice，有 poppler(pdftoppm）即可
- PPT 输入：必须有 LibreOffice 渲染器（soffice)

```bash
which pdftoppm      # PDF 必需
which soffice       # PPT 必需
```

PPT 输入但无 soffice 时，停止并回报主代理。

### 1.3 工作目录

```
<工作区>/ppt-parse-working/<任务名>/
```

```bash
python <skill_scripts_dir>/parse.py <输入文件路径> \
  --out "<工作区>/ppt-parse-working/<任务名>/初稿_<文件名>.docx" \
```

确认产出：

## 3. 阶段二：逐页视觉校准（核心，占工作量 50%)

> 必须一页一页串行处理。每识别一页，当场校正文字顺序、插入图片标记、确认无误后再翻下一页。严禁批量处理多页。

### 3.1 读取 extracted_text.json

了解每页文字块数量和嵌入图片数量。每页 `images` 数组长度 = 本页最多图片标记数。

### 3.2 读图分层策略

| 层级 | 读取对象 | 目的 |
|------|---------|------|
| 第一层 | `page_NN.png` 整页截图 | 判断页面类型、结构、图片分布（只看大概，不细读） |
| 第二层 | `extracted_pics/` 高清原图 | 复杂信息图的逐字转录 |

何时进入第二层：图表/数据图等核心信息图、整页截图中小字模糊、结构复杂的流程图/架构图。

### 3.3 逐页处理流程

**1 确认本页嵌入图片数量 N**
- 看 `extracted_text.json` 本页 `images` 数组长度
- 标记数不超过 N 即可
- PPT/PDF 原生绘制的形状、框图、连接线、SmartArt **不是嵌入图片**，不要加 pic 标记

**2 第一层：read 整页截图**，判断：
- 本页类型：文字为主页 / 图片为主页
- 每个嵌入图片类型：辅助配图 / 核心信息图
- 是否存在“文本组成的图表”（见 3.4）

**3 对照脚本提取的文字 + 整页截图，按视觉逻辑重排文字顺序**

> ⚠️ **标点符号保真（绝对规则）**：
> - `extracted_text.json` 中的文字是原始文本，**只能重排顺序，不能改写**
> - **禁止**更改任何标点符号，特别是中英文引号（如 `""` 与 `""` 不得互换）
> - **禁止**将中文标点改为英文标点，也**禁止**将英文标点改为中文标点
> - **禁止**增添、删除、替换任何字符（除非明确发现原文错字，此时加批注说明，不直接修改）
> - 原文是什么，就是什么。哪怕原文标点“不规范”，也原样保留
> - 操作方式：从 `extracted_text.json` 中**逐字复制**文字块，只调整文字块之间的排列顺序

- 按空间距离分组：紧挨在一起的文字归为一组，用空行分隔不同组。视觉上紧挨在一起的多个名称往往是对上方的举例，应归为一组，不要拆成独立条目跟分类并列
- 按视觉阅读顺序：从上到下、从左到右
- 结构图/谱系图里的文字框：脚本已提取，按层级关系用缩进/换行表达结构
- 不要凭空编造不存在的图片

**4 按图片类型分类处理嵌入图片**

辅助配图（logo、照片、截图、装饰图等）:
  - 一句话简述即可，不逐字读小字
  - 典型场景：报纸版面（识别出是XX报、报道标题即可，不读正文小字）、杂志版面、网页截图（识别是什么网站的什么页面即可，如文字未提及不需要完整识别导航元素等细节）、弱相关的密集文字长图（简述内容主题即可）
  - 格式：
```
/[pic NN：简述]/
```

核心信息图（图表、流程图、架构图、表格、数据图等）:
1. 第二层：read `extracted_pics/` 中的高清原图
2. 逐字转录图中所有文字（标题、坐标轴、图例、数据、注释等）
3. 块级标记包裹：
```
/[pic NN]***
图表类型:XXX
标题:XXX
横轴/纵轴:XXX
数据:
- ...
图例:XXX
***/
```

装饰性元素（形状、背景、分隔线、角标）:不标记。

**5 图文绑定**:图片标记紧贴对应文字，不分离。
- 正确：`第一梯队 /[pic 01：微信]/ /[pic 02：微博]/`
- 错误：先写一堆文字再统一列图片说明

**6 确认本页输出正确，再处理下一页。**

### 3.4 “文本组成的图表”处理

页面上看起来是图表/流程图，但 `extracted_pics/` 中没有对应图片--这些是 PPT/PDF 中的文本框 + 矢量图形组合，不是嵌入图片。

处理方式：
1. read 整页截图识别其中的文字内容
2. 按层级结构整理文字，用缩进/换行表达逻辑关系
3. 不加 `/[pic]` 标记
4. 如果文字密集、结构复杂，添加批注

### 3.5 批注规范

遇到以下情况时添加批注：
- 文本组成的图表，识别难度较大
- 图片模糊，无法准确转录
- 文字顺序不确定
- 其他需要主代理特别注意的地方

格式：`<!-- 批注：具体内容 -->`

## 4. 生成初稿 docx

### 4.1 文档开头

```
<!-- 本文档解析自文件：[文件名]，合计 X 页。
标记说明：
  /[pic NN：简述]/   -> 行内小图（logo/照片/截图）
  /[pic NN]*** ... ***/  -> 块级大图（图表/脑图/流程图，需细读）

```

### 4.2 每页结构

```
page N
【此处插入整页截图】
[文字内容按逻辑顺序排列,图片标记紧贴对应文字]
```

### 4.3 保存

- 文件：`初稿_<文件名>.docx`
- 位置：`<工作区>/ppt-parse-working/<任务名>/`
- 保留 `_assets/` 素材目录供主代理复核

## 5. 标记符号系统（完整副本，修改时须同步 SKILL.md)

**所有标记用 `/.../` 包裹。**

### 图片标记

| 标记 | 适用场景 | 要求 | 示例 |
|------|---------|------|------|
| `/[pic NN：简述]/` | 辅助配图：logo、照片、报纸/杂志版面、网页截图、弱相关密集文字长图、装饰图 | 一句话简述，不读小字 | `/[pic 01：微信logo]/`、`/[pic 02：每日新报终刊版面]/` |
| `/[pic NN]*** ... ***/` | 核心信息图：图表、流程图、架构图、数据图等 | 逐字转录所有可见文字 | 见下方格式 |

### 编号规则
- 每页独立编号，按从左上到右下顺序
- 编号数量与脚本 `images` 数组长度一致
- 无嵌入图片的页面不加任何 `/[pic` 标记

### 文字部分
- 无标记文字 = PPT/PDF 可编辑文本（经视觉核对顺序）
- 块级标记内文字 = 视觉识别/OCR 结果
- 整页截图嵌入 docx，放在每页标题下方
